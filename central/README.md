# central

Pi C 중앙통제: Pi A(손 끼임), Pi B(쓰러짐)의 탐지 결과를 받아 위험 단계(0~3)를 판단하고 ESP32에 명령한다.
메시지 형식과 규칙은 통신 약속 문서를 따른다.

## 실행
저장소 맨 위에서 실행한다 (`central.rules`를 불러오기 때문).
```
python -m central.main     # 중앙 프로그램
python -m central.rules    # 판단 규칙 시험
```
노트북에서는 브로커 주소가 `localhost`, 파이에서는 `ss-central.local`.

## 파일
| 파일 | 하는 일 |
| --- | --- |
| `main.py` | MQTT 수신, 형식 검사, 장치 끊김 감지, 단계 출력 |
| `rules.py` | 위험 단계 판단 함수 `decide_level` + 시험 |

## 흐름
```
[MQTT 수신 스레드]  메시지 -> 형식 검사 -> latest, last_seen 저장
[메인 while, 1초]   장치 정상 여부 -> 인원 부족 시간 -> decide_level -> 유지 규칙 -> 바뀌면 출력
```

## 받는 메시지 처리 (통신 약속 3-4)
아래 중 하나면 **버리고 이유를 출력**한다. 버린 메시지는 "살아 있음"으로 치지 않는다.
1. JSON이 아님
2. JSON 객체(`{...}`)가 아님 (예: `5`, `[1,2]`)
3. 모르는 토픽 (`stillsafe/hand`, `stillsafe/fall`만 받음)
4. 토픽별 필수 값이 빠짐

## 위험 단계 판단
높은 단계부터 검사하고, 처음 걸리는 것을 쓴다.

| 단계 | 이유 (`reason`) | 조건 |
| --- | --- | --- |
| 3 | `device_error` | 장치 하나라도 정상 메시지가 3초 넘게 없음 (한 번도 못 받은 것 포함) |
| 3 | `hand_inner` | 손 안쪽 구역 |
| 3 | `fall` | 쓰러짐 확정 |
| 2 | `hand_outer` | 손 바깥 구역 |
| 1 | `two_people` | `people < 2`가 3초 이상 이어짐 |
| 0 | `safe` | 해당 없음 |

- 올라갈 때는 바로 바뀐다.
- 주의(1), 경고(2)에서 내려갈 때는 낮은 판단이 2초 이어져야 내려간다 (깜빡임 방지).
- 지금은 GPIO 대신 MQTT 메시지의 `signal` 값으로 판단한다 (6단계에서 GPIO로 교체).

## 설정값
| 이름 | 값 | 뜻 |
| --- | --- | --- |
| `TIMEOUT_SEC` | 3 | 장치 끊김 기준 |
| `HOLD_SEC` | 2 | 주의·경고 유지 시간 |
| `TWO_PERSON_SEC` | 3 | 인원 부족 지속 기준 (**팀 미정**, 임시값) |

## 진행 상황
| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1 | MQTT 수신 | 완료 |
| 2 | 형식 검사 | 완료 |
| 3 | 장치 끊김 감지 (3초) | 완료 |
| 4 | 위험 단계 판단, 인원 부족 지속, 2초 유지 | 완료 |
| 5 | ESP32 시리얼 (`PING`, `LEVEL`) | |
| 6 | GPIO 위험 신호 읽기 | |
| 7 | 로그 CSV | |
| 8 | 재가동 흐름, 위험 잠금 | |

## 아직 안 된 것
- 위험(3)이 자동으로 풀림 -> 8단계에서 잠금으로 바꿈
- 모터가 돌 때만 경보 -> 5단계 이후 (ESP32 모터 상태 필요)
- 판단 간격 1초라서 빠르게 깜빡이는 신호를 놓칠 수 있음 -> 5단계에서 간격 줄임
- `stillsafe/status/*` (Last Will) 처리
